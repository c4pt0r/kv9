# Applied receipt representation: source mapping and limits

The candidate is `74d241161eadf2121128f6fd9101ead18e562765`, compared with CRC `ca0002c7f8e9ee6f595efcc9f4151085ccce87cb`. Exact Rust and local Rust 1.94 documentation hashes are recorded in `source-mapping.json`. This is a conditional local refinement argument, not whole-Rust or Raft correctness.

`ARVectorPush` maps to the original vector append then oldest-prefix drain. `ARDequePush` maps to candidate `AppliedRing::push`: when reachable length equals the unchanged capacity 1024, pop the front, then append. Reachable length never exceeds capacity, so the vector removes at most one element. The equality theorem covers every positive capacity and preserves the complete index/term/outcome sequence, hence length, first/last and every retained receipt.

`ARCertificate` maps to the exact checked Boolean conjunction before eviction. No incoming index ordering is assumed. Duplicates, decreases and any later reordering make the flag false permanently. Under a true flag the inductive invariant gives strict ordering and uniqueness. False selects the original first-match iterator. The proof preserves full payload and absence, not just successful writes; `inspect_applied` still uses the retained receipt term and exhaustive exclusive outcome. Queries outside a small finite TLC set are covered in the parameterized statement by instantiating the index domain with all u64 values.

The standard library is trusted at its documented sorted-search boundary: on a sorted deque, a returned match has the queried key and no match is returned exactly when absent; duplicate keys may select any matching position. Strict ordering removes that freedom. The supplied Rust 1.94 source documentation explicitly makes unsorted search unspecified. `ARAny` describes the permitted logical result, not Rust's algorithm; TLC's deterministic CHOOSE should not be mistaken for exhaustive malformed-search outcomes. The certificate control therefore checks the actual false ordering certificate, independently of which duplicate TLC's CHOOSE happens to select.

No source extraction, allocator/OOM, mutex proof, whole Ready/apply composition, cancellation, liveness or crash durability theorem is added. The local sequential ring model composes only conditionally with unchanged caller synchronization and library operations. Existing source/process/performance evidence remains separate.
