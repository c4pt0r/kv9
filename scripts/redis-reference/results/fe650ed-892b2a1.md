## Outcome certainty and residual work

Both revisions recorded zero UnknownWrite, admission refusal, NotLeader refusal, read failure, or client rejection in measured calls. Every retained after-verification snapshot had zero queued, running, and in-flight backend jobs and encoded-byte reservations. These snapshots are asynchronous observations, not an atomic quiescence guarantee.

UnknownWrite means the client did not establish the outcome; it is not proof that the write failed. Configured client concurrency does not bound outstanding backend jobs after caller cancellation. After snapshots are captured after client drain and final verification; they are not atomic across nodes. Trials use the same persistent KV9 fixture, so retained background work can affect subsequent trials. A fast-refusal population can dominate aggregate terminal latency; acknowledged latency must be reported separately.

Workers can issue new logical operations after fast explicit refusals. They never retry a prior uncertain write. Where refusals dominate, aggregate terminal percentiles largely describe refusals; the following percentiles include acknowledged calls only. Values are histogram intervals, not exact percentile estimates.

## CPU headroom and measurement limits

At concurrency 64, the candidate read client used 0.991–0.993 CPU cores out of its two allowed CPUs, and its busiest thread used at most 0.497 cores. The three database processes together used 3.590–3.603 cores out of four allowed CPUs. The Redis reference client used 1.356–1.394 cores across the three mixes, with its busiest thread below 0.700 cores, while its server used approximately one core. Both clients had CPU headroom under this protocol.

Candidate pure-write trials used only 0.020–0.027 client cores and 0.119–0.136 aggregate server cores at concurrency 64. This leaves substantial CPU headroom but does not alone identify the limiting wait. Root's separate work stayed on logical CPUs 6–31, which can still share physical-core and storage resources. No other owned runtime stress fixture or archive compression was deliberately run during these timed trials.
