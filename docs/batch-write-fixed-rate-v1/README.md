# Fixed-rate BatchPut reporting evidence

This bundle retains the original four correctness-smoke and eight timed native BatchPut(64) cohorts, the frozen driver and clients' source/build bindings, exact raw reports and histogram populations, independent readback, derived statistics and root terminal receipts. The timed protocol offers 800,000 batch calls across 8,000 and 12,000 calls/s, c64 and ten-second cells in complete forward/reverse order. It compares the retained CRC server with integrated ThinLTO; no server or client was changed or rebuilt for this diagnosis. No Redis trial ran.

Equal offered rate does not establish equal realized work. The exact statistics keep issued, dropped, completed, refused, unknown, retry and cutoff populations separate. Whole-call, scheduled-to-completion and dispatch-lateness distributions cover issued terminal calls only; dropped slots receive no invented latency. Means use original sums/counts and quantiles merge raw buckets. Batch latency is never divided by 64. Each original order is visible in PER-REPEAT.md, with pooled results in READOUT.md. This diagnostic does not automatically promote a candidate or erase the earlier closed-loop BatchPut p99 regression.

Three voters retain ordinary quorum and sync calls on volatile tmpfs WAL. This is a shared-host loopback comparison, not durable-media latency, Redis write-durability equivalence, sustained capacity, statistical significance, independent host-failure acceptance or full-history linearizability proof. Source-bound recovery and earlier actual Chaos Mesh evidence keep their original scopes; this experiment adds no new Chaos run or core proof.

The first actual independent audit validated all eight cohorts, then failed in an obsolete Redis pairing check excluded by this native-only protocol. The corrected reader deletes that six-line check; every existing function and the statistics core are unchanged. A focused complete-eight post-loop regression reproduces the original failure and accepts the correction. Both preparations, the original failing terminal/log and the corrected replay are retained. No performance cohort was rerun. Preparation-only control/constructor failures also remain visible.

Capacity preparation and exact private Cargo cache retirement receipts are included. The retirement reclaimed rebuildable test/compiler outputs after locked inode/reference checks and byte hashing; all affected profile fingerprints were invalidated and retained externally. Original runtime binaries were hashed before and after. Historical compression estimates are operational scenarios, not proven bounds; all original storage floors, caps and runtime guards remain unchanged.

inventory.json maps reporting files to original paths, byte lengths and SHA-256 hashes. The archive consists of numbered parts of at most 2 MiB. Run `python3 verify.py` to check exact reporting bytes without extraction. WALs, compressed data objects, retained executable payloads, retired fingerprint trees, GitHub API bodies and credentials are excluded before payload reads. Their original accepted inventories/catalogs remain authoritative. This is a reporting bundle, not a data backup or a portable standalone full-runtime re-audit.
