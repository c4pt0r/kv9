# DATA 保留 placement 历史的有界盘点

开始：2026-10-05；验证延续至 2026-10-06。接续 [DATA 读下限独立确认](RAW-TTL-DATA-FENCE-OBSERVATION.md)。
本增量为后续 DATA 旧镜像关闭建立可能持有数据的 store 目录，已完成下述本地组件验证。
它只盘点仍保留的 placement 任务，不证明全体实际历史成员、Reader、安装、备份或
恢复来源都已覆盖，不授予 Pending/Version 释放或对象删除权限；第二阶段仍开放。

## 保留来源与变化检测

metadata 的 MetaTxn 在 TASKS 插入、更新和删除的同一个批次中写入固定 49 字节的
修订记录，包含校验和、单调序号和不可清除的不确定历史标志。一次事务内连续操作
读取自己的修订；失败操作不会留下部分 overlay。无变化的更新及删除不存在的行
不推进序号。删除或重写不可变任务使历史不确定，后续插入不能清除该状态。相同
kind 102 的 range binding 更新可以继续使用，但会使此前盘点修订失效并重新扫描。

保留目录包含创建任务的全部初始 store，以及迁移目标、安装凭据、源移除和迁移
中止记录中的精确 store incarnation。已经移除的副本、已经中止的目标不会被过滤。
每个来源保留 region、creation digest、node、incarnation、task、kind 与原始行摘要。
其他已知任务（激活、范围绑定、截断、split、压缩）沿精确引用验证；未知 kind、
非零 phase、坏编码、错 root、缺少前驱或不一致引用均不能得到完成状态。

投影只使用固定深度的任务点读，不调用累积全部迁移/激活历史的旧枚举接口。每次观察或提交规划
最多处理四个任务，额外看一行判定是否有后续；同一页在观察和提交时可以重复读取。
每个任务最多产生七个来源。全部目录历史仍被保留，这个单页预算不构成历史总量或整机 RSS 的界限。

## 持久进度和查询完整性

retention header 升为 KV9LED22；namespace 49 保存来源，50 保存进度，51 保存
每组来源数量。请求 tag 37 只携带预期页序号、任务修订与起点；下一游标及写入内容
由同一 metadata 快照推导，调用者不能跳过页面。来源、数量、进度随 metadata Raft
原子提交。精确上一页丢回执可重试；它只是历史确认，不能使已经变化的目录再次完成。

任务修订变化时从头补扫，已经保存的来源不删除；修订丢失或回退明确拒绝。
任务删除或不可变行变更保持 Uncertain，不将空扫描当作历史完整性的证明。

查询要求当前任务修订的盘点完成，返回最多四个来源和固定组的总来源数，并逐行
验证原始任务摘要和引用。分页 cursor 由查询构造，绑定组、creation、任务修订和
已见数量，不能跨组借用或跨修订续用。计数缺失、索引短缺或多出行均拒绝完成查询；
空页不证明没有历史来源。同一 store 的不同任务来源可以重复出现，计数计算来源行，
不是去重后的 store 数。后续关闭协议仍须按精确 store 汇总，并重新核对目录修订。

## 后台调度与升级

已有 checkpoint sweep 在 Build、Reader、Bootstrap、镜像 Reader/Publisher 目录
完成后推进一页 DATA placement 盘点，复用原共享维护槽位、读屏障、leader 校验、
deadline 和取消规则，不进行对象 I/O。状态输出 data_store_history 的页数、检查行数、
当前观察修订、保留目录完成和不确定标志。目录完成只描述所观察的快照；新任务提交
会使下一次观察重新扫描。高频拓扑变化下的收敛时间仍待资格验证。

旧 metadata writer 不能绕过修订记录继续写入，因此磁盘与内部服务 floor 同步升为
V11。冻结的 V10 codec/proto 用于检验旧 reader/服务拒绝新格式和双向无降级；保留
原有全部冻结 fixture。Active V10 升级前也必须存在持久 DATA 读下限目录，不能通过
升级重建一个丢失的目录。V11 属于协调升级边界，不表示实际旧二进制滚动升级已验收。

## 验证边界

本地元数据测试覆盖中止/移除来源、游标之后的早期任务插入、重复页、跳页拒绝、
未知/破损任务、不可清除的历史不确定、修订丢失、来源计数与分页隔离、实际扫描预算，
以及磁盘 WAL 重开。运行态测试使用实际三副本 raft-rs、磁盘 WAL/Raft 和鉴权
HTTP/2 duplex：提交后丢回执、换主、自动续做、完成后新建组触发补扫、全部副本
WAL 重开，既有 Pending pins 始终保留。

[验证包](raw-ttl-data-store-history-validation-20261005/manifest.json)保留命令、原始失败、
源码摘要及负向对照。529 个不同 Rust 测试通过，1 个既有测试忽略；新增 16 项。
metadata 全套 333 项、common 85 项、内部格式 11 项、DATA floor RPC 2 项，以及
串行 TTL runtime 98 项通过。重复的定向测试不重复计数；空的 sweep 过滤器不增加覆盖。
严格 workspace Clippy（含 write-stage-tracing、checkpoint-testing）、格式、diff 和
三个相关脚本语法检查通过。负向对照临时移除任务修订回退检查后，新测试按预期失败；
原始检查恢复后完成上述验证。八份既有受保护源码及之前封存的证据保持不变。

**仍有并发回归稳定性缺口。** 四个测试线程的第一次完整回归 97/98 通过，剩余是
迁移升级 fixture 仍断言 V10；修正为 V11 后，第二次四线程回归也为 97/98，其中
DATA floor 的正向 checkpoint 交接返回 outcome-unconfirmed。该用例随后单独通过，
再以一个测试线程完成全部 98 项；没有放宽断言或生产超时。RPC 将非 NotLeader
后台错误及传输失败合并为同一结果，因此现有日志不能确定原始原因，串行通过不证明
四组 fixture 并发稳定或生产负载资格。两次失败均保留，后续需要捕获原始错误并复现。

使用实际 raft-rs、磁盘 WAL/Raft、鉴权 HTTP/2 duplex 和内存对象存储；没有新增真实
TCP/MinIO、跨主机、旧二进制、进程 kill、长期负载或完整协议证明。此包封存组件
进展与已知缺口，不能作为完整阶段或生产验收。
